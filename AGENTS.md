# RedisShake Project Rules

## Verification and Remote Push

- After completing any code, configuration, documentation, asset, or project-structure change, run verification appropriate to the change.
- If verification passes, commit all in-scope changes and push the commit to the corresponding remote branch before declaring the task complete.
- If verification fails or cannot be completed, do not push the change. Report the failure or verification boundary to the user instead.
- Never include unrelated local changes, generated build output, dependencies, credentials, or secrets in the commit.
